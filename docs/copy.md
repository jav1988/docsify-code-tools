# docsify 代码复制插件 使用说明

适用版本：**v2.4.0**（新版 `docsify-copy-code-v2.js`）

给代码块加一个复制按钮：鼠标移上去按钮浮现，点一下代码进剪贴板。

---

## 一、这个目录里有两份

| 文件 | 说明 |
| --- | --- |
| `docsify-copy-code-javen.js` | 你原来的那版，保留着没动 |
| `docsify-copy-code-v2.js` | 重写的新版，推荐用这个 |

**两份只能引一份**，同时引会出现两个按钮。

---

## 二、接入

把 `index.html` 里原来那行换掉：

```html
<!-- 原来 -->
<script src="_plugs/docsify-copy-code-javen.js"></script>

<!-- 换成 -->
<script src="_plugs/docsify-copy-code-v2.js"></script>
```

---

## 三、配置

原来那三个文案配置完全照旧，连「按路径取不同文案」的写法也认：

```js
copyCode: {
    buttonText: '复制',
    successText: '已复制',
    errorText: '复制失败'
}
```

| 配置项 | 默认值 | 用在哪儿 |
| --- | --- | --- |
| `buttonText` | `复制` | 悬停提示（tooltip）与读屏标签 |
| `successText` | `已复制` | 复制成功时的提示与读屏标签 |
| `errorText` | `复制失败` | 复制失败时的提示与读屏标签 |
| `opacityIdle` | `0.72` | 鼠标不在代码块里时的透明度，写 `0` 就是平时看不见 |
| `opacityInCode` | `0.9` | 鼠标进了代码块时的透明度 |
| `opacityOnButton` | `1` | 鼠标停在按钮上时的透明度 |

新版是图标按钮，不再显示文字，所以这三个文案转去做悬停提示和屏幕阅读器标签，功能照旧。

---

## 四、新版做了什么

**按钮位置从右上角挪到左上角**（`left: 68px; top: 5px`，让开那三个小圆点）。这是必要的：原来它在 `right: 0`，而语言标签在 `right: 12px`，两者实测重叠 31×20 像素，悬停时会压住语言名的右半边。

**复制改用 `navigator.clipboard`**，旧浏览器或非安全上下文回退到临时 textarea。两条路都不动你在正文里的选中。

**反馈有了手感**：

| 状态 | 按钮上显示 | 动作 |
| --- | --- | --- |
| 平时（鼠标在代码块外） | 剪贴板图标 + 「复制」 | 半透明（0.72），看得见但很轻 |
| 鼠标进了代码块 | 同上 | 清晰一档（0.9），提示这里有东西 |
| 鼠标停在按钮上 | 同上 | 最清楚（1），底色加深 |
| 按下 | 不变 | 缩到 0.94 |
| 成功 | 对勾图标 + 「已复制」 | 对勾自己一笔画出来（0.36 秒），按钮轻弹一下并转淡绿 |
| 失败 | 叉图标 + 「复制失败」 | 转淡红，静态 |

**图标和文字一起给。** 认得剪贴板形状的人看图标，不认得的看旁边那两个字，两边都不落空。

**平时不再完全隐身**（透明 0.72，不是 0）。上一版靠悬停才显形，结果是很多访客根本不知道那里有个按钮，这一版让它一直看得见但很安静。

**透明度分三档，而且三档都能配**：默认 `0.72 / 0.9 / 1`。鼠标扫过代码块时按钮亮一档，等于告诉人“这里可以点”；真的对准它时才是最清楚的。

这是口味问题，没有标准答案，所以三个值都开了出来：

| 配置项 | 默认值 | 管的是 |
| --- | --- | --- |
| `opacityIdle` | `0.72` | 鼠标不在代码块里时 |
| `opacityInCode` | `0.9` | 鼠标进了代码块 |
| `opacityOnButton` | `1` | 鼠标停在按钮上 |

想让它平时完全看不见（靠悬停才现身），把第一档写 `0`：

```js
copyCode: {
    opacityIdle: 0
}
```

想让它一直明显，三档都写 `1`。

除了配置，也可以用自己的 CSS 覆盖同名变量：`--copy-opacity-idle`、`--copy-opacity-code`、`--copy-opacity-button`。

**鼠标点完之后按钮会主动失焦。** 按钮一旦留住键盘焦点，`:focus` 那条样式会把它钉在全亮状态，非要去别处再点一下才松手。现在只在鼠标点击时让它失焦，键盘触发（Enter / 空格）的不动，键盘用户依然能靠焦点看见按钮。

**触摸设备上完全不透明**（`@media (hover: none)`），手机上看着才不发灰。

**事件委托从 `.content` 挪到 `document`**，并加了手写向上查找，不依赖页面结构也不依赖 `closest`。原来绑在 `.content` 上，那个元素一旦不存在就会抛异常。

## 五、兼容性

| 环境 | 走哪条路 |
| --- | --- |
| HTTPS / localhost，现代浏览器 | clipboard API |
| http 的非 localhost 地址 | 回退到 textarea |
| Chrome 66 以下 | 回退到 textarea |
| 权限被拒、调用失败 | 先用 clipboard，失败**自动回退** |
| iOS Safari 13.4+ | clipboard API |
| 更早的 iOS Safari | 回退（已补 `setSelectionRange`，否则选不中） |

**要说明的一点**：回退那条路靠「选中文字再复制」实现，所以它必然会动到页面选中状态，复制完会清掉但**无法恢复你原来选中的内容**。这是老办法的固有缺陷，主路没有这个问题。

## 六、运行时可调

```js
window.DocsifyCopyCode.refresh();   // 给新渲染出来的代码块补按钮
window.DocsifyCopyCode.version;     // 版本号
```

## 七、常见问题

**出现两个按钮**

引了两份。删掉 `docsify-copy-code-javen.js` 那行。

**按钮和语言标签打架**

那是旧版的问题，新版把按钮挪到了左上角。

**手机上看不到按钮**

旧版才有这个问题。新版在触摸设备下让按钮常显。

**复制成功但粘贴出来是空的**

极老的环境下 clipboard API 和 textarea 都可能失败，按钮会显示「复制失败」。告诉我你的浏览器和访问地址（是 https 还是 http），我对着看。
